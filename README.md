# SimBridge SCADA

WPF / .NET 10. Открыть SimBridge Scada.slnx в Visual Studio и запустить F5.

## Структура

- Shell/View/MainWindow.xaml.cs — запуск выбранного режима, жизненный цикл окна и публичные методы открытия/сохранения.
- Modes/IApplicationMode.cs — интерфейс режима приложения.
- Modes/Editing/EditingMode.cs — настройка редактора: сервисы, регистрация типов, панели, команды, горячие клавиши и диалоги.
- Project/Models — манифест проекта и описание схемы.
- Project/Services — IProjectService, ProjectService, работа с ZIP и временной папкой.
- LeftPanel/View и ViewModel — библиотека, иерархия, список рабочих областей, левая полоса иконок.
- RightPanel/View и ViewModel — Inspector и правая полоса иконок.
- Components/Common, ObjectProperties, Transform, Image, Text, Symbol — базовые и конкретные компоненты со своими редакторами.
- Workspaces/Core — SchematicWorkspace, состояние отдельной схемы и её горячие клавиши.
- Workspaces/ViewModel — менеджер документов и рабочая область.
- Workspaces/View и Controls — вкладки, отрисовка, мышь, масштаб и навигация.
- Workspaces/Elements — пустой объект и готовые объекты оборудования, шаблоны символов.
- Workspaces/Persistence — сериализация отдельной схемы и поддержка старого JSON-проекта.
- Shared/Sidebars, Menus, FileDrop — общие элементы панелей, контекстные меню и загрузка перетаскиванием.
- Infrastructure и Themes — команды, уведомления, конвертеры и тёмная тема.

## Сервис проекта

Основной формат проекта — **.simbridgescada**. Это ZIP-архив со всем содержимым проекта: схемами, иерархией, компонентами, изображениями, дополнительными данными и состоянием вкладок.

В EditingMode создаётся ProjectService и передаётся менеджер схем, WorkspaceStorage и фабрика документов. Сервис доступен как MainWindow.ProjectService через интерфейс IProjectService. Методы MainWindow.SaveProject и LoadProject показывают диалоги и делегируют операции сервису. Сериализация, рабочие файлы и упаковка находятся в сервисе.

Рабочая папка создаётся рядом с исполняемым приложением:

```text
ProjectTemp/
  <идентификатор экземпляра приложения>/
    Current/
      project.json
      Schemes/
        <Id схемы>.json
      Assets/
        Images/
          <хеш содержимого>.png
      Data/
        ...будущие настройки и другие данные...
```

Каждый экземпляр приложения получает отдельный каталог, поэтому параллельные запуски не перезаписывают рабочие копии друг друга. Папка приложения должна быть доступна для записи. Рабочие копии остаются после закрытия приложения; они не входят в пользовательский архив как отдельные сеансы.

Сервис отслеживает изменение документов, объектов, компонентов и вкладок. При наличии изменений рабочая копия обновляется с задержкой до двух секунд. Это не сбрасывает `*`: звёздочка исчезает после сохранения пользовательского архива. FlushWorkingCopy позволяет записать рабочую копию немедленно. LastWorkingCopyError сообщает об ошибке обновления временных файлов.

### API

Все методы вызываются на UI-потоке. Основные операции:

```csharp
IProjectService project = ProjectService;

var schemes = project.GetSchemes();                // Id, имя, количество объектов, состояние, путь рабочего файла
var document = project.GetScheme(id);              // живая схема либо null
var data = project.GetSchemeData(id);              // отдельный DTO схемы
project.AddScheme(data);                            // восстановить и добавить DTO
project.SaveScheme(id);                             // записать рабочую копию
project.DeleteScheme(id);                           // удалить схему и обновить рабочие файлы
project.FlushWorkingCopy();

project.WriteData("Settings/config.json", bytes); // будущие данные проекта
var bytes2 = project.ReadData("Settings/config.json");
var files = project.GetDataFiles();

project.SaveProject(@"C:\Projects\Station.simbridgescada");
project.LoadProject(@"C:\Projects\Station.simbridgescada");             // заменить текущий каталог
project.LoadProject(@"C:\Projects\Other.simbridgescada", merge: true); // добавить схемы
```

Для запросов не требуется разбирать архив или искать файлы вручную. WorkingDirectory, SchemesDirectory, DataDirectory и CurrentFilePath дают пути проекта. HasChanges учитывает также добавление/удаление схем и дополнительные данные, а не только свойства объектов.

### Сохранение и загрузка

Ctrl+S сохраняет весь проект в .simbridgescada, в том числе когда фокус находится в Inspector или открытых вкладок нет. При первом сохранении выбирается файл. «Сохранить проект как…» выбирает новый путь. Кнопка сохранения всех областей слева использует тот же сервис.

При сохранении изображения копируются в Assets/Images, а пути в файлах схем заменяются относительными путями внутри проекта. Оригинальный путь компонента в текущем редакторе менять не требуется. Поэтому проект переносится на другой компьютер вместе с изображениями. Если указанный непустой путь не существует, сохранение завершается ошибкой, не заменяя предыдущий архив.

Новый архив сначала полностью записывается во временный файл и только затем заменяет старый. Отметки изменений снимаются после успешного завершения. Дополнительные файлы из Data также включаются в ZIP.

При загрузке архив распаковывается в отдельную временную папку. До применения проверяются манифест, типы объектов и компонентов, связи иерархии, ссылки на изображения и конфликты дополнительных данных. Путь из архива не может выходить за пределы рабочей папки. Ограничения формата: до 5000 схем, до 10000 файлов, до 32 МБ на схему и до 512 МБ распакованных данных.

MainWindow.LoadProject заменяет весь текущий проект сохранённым содержимым, включая схемы с совпадающими Id. Перетаскивание файлов использует отдельный импорт с merge: true; при таком импорте схемы с совпадающими Id не дублируются. При объединении различающиеся дополнительные файлы с одинаковым путём приводят к ошибке, а не перезаписываются молча.

Старые .simbridge и .simbridge-project можно открыть через общий диалог или перетащить в редактор. Они загружаются как схемы старого формата; следующее сохранение полного проекта использует .simbridgescada. Явный SaveWorkspace(document, path) остаётся экспортом одной схемы для совместимости. Путь .simbridgescada всегда направляется в сохранение полного проекта.

## Рабочие области и панели

На старте создаются три пустые схемы, две открыты. Начальный состав задаётся в EditingMode.cs. Вкладки можно выбирать, закрывать и переставлять перетаскиванием. Закрытие вкладки оставляет документ в каталоге. В панели «Рабочие области» доступны создание, открытие файла и сохранение всех областей; правый клик по строке или вкладке открывает действия, включая переименование и удаление.

На каждой стороне открывается одна панель. Повторный щелчок иконки закрывает её. Панели закреплены; разделители меняют ширину. SidebarButtonViewModel хранит иконку и либо открываемую панель, либо произвольный Action.

Правый клик открывает контекстные меню. Левый выполняет обычные выбор, открытие и перетаскивание. Кнопки «Файл» и «Добавить компонент» настроены на левую кнопку явно. Для нового элемента меню достаточно ILeftClickMenuProvider и attached behavior LeftClickMenu.IsEnabled; MouseButton задаёт нужную кнопку.

## Объекты, иерархия и компоненты

В иерархии есть раскрывающиеся ветки. Перенос на середину строки делает объект дочерним, на край строки меняет порядок, в пустую область — делает корневым. Перенос сохраняет мировое положение. Циклы и перенос между схемами запрещены. При удалении родителя удаляется ветка.

У каждого объекта есть обязательные компоненты «Объект» и Transform. Позиция Transform локальна относительно родителя; WorldX/WorldY/WorldRotation вычисляются для отрисовки. Потомки следуют за движением и вращением родителя и наследуют его видимость/включённость. Отдельного Scale пока нет.

Пустой объект ничего не рисует, кроме рамки выделения. Внешний вид добавляется компонентами изображения, текста или символа оборудования. Готовые насос/задвижка/резервуар являются пресетами с компонентом символа.

В Inspector есть «Добавить компонент». Дополнительных компонентов одного типа может быть несколько. Правый клик по заголовку позволяет переместить компонент вверх/вниз и удалить. Обязательные компоненты удалять нельзя. Порядок определяет также наложение визуальных компонентов.

Каждый компонент имеет свой UserControl рядом с ViewModel в Components/<тип>/. Новые типы регистрируются в EditingMode и WorkspaceTypeRegistry; их публичные редактируемые свойства должны поддерживать System.Text.Json и уведомления INotifyPropertyChanged. Для отрисовки используется отдельный шаблон Visual.ИмяКлассаViewModel.

## Управление

- Средняя кнопка мыши — перемещение просмотра.
- Колесо — масштаб относительно указателя; диапазон 25–200%.
- Delete — удалить объект с потомками, Escape — снять выделение.
- Ctrl+0 — масштаб 100%, Ctrl+W — закрыть вкладку.
- Ctrl+S — сохранить проект, Ctrl+O — открыть файл, Ctrl+N — создать схему.

Рабочая область 2400 × 1600, фон #262626, точечная сетка 20 px. Чтение данных ПЛК реализовано через Modbus TCP; трубопроводы пока не реализованы.

## Modbus TCP

Кнопка с сетевой иконкой в левой панели открывает отдельное окно Modbus. Повторное нажатие активирует уже открытое окно. Укажите IP, порт (обычно 502), Unit ID, период и таймаут. Кнопка «Тест» проверяет TCP-подключение и читает первую переменную, если таблица заполнена. «Начать опрос» включает обновление всех переменных, «Остановить» прекращает опрос. Закрытие окна оставляет запущенный опрос работающим для компонентов текста. Изменение настроек останавливает опрос; после ошибки связи выполняется повторное подключение.

В таблице редактируются уникальный неотрицательный индекс, тип данных, область Modbus, адрес со смещением от нуля, порядок байтов и комментарий. Рядом отображаются значение и состояние. Поддерживаются Boolean, UInt16/Int16, UInt32/Int32, Float32/Float64; Coils, DiscreteInputs, HoldingRegisters и InputRegisters (функции 01–04). Запись в устройство не выполняется. Для битовых областей используется Boolean. Для многорегистровых значений настраивается BigEndian, WordSwap, ByteSwap или LittleEndian. Адрес 0 соответствует первому адресу выбранной области; обозначение 40001 вводить не нужно. Спецификация: https://www.modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf

В компоненте «Текст» включите «Синхронизация с Modbus» и выберите индекс переменной. На схеме появится её значение. При отключённом опросе, ошибке или отсутствии индекса отображается «—». После отключения синхронизации снова отображается поле «Содержимое». Обновления значений не меняют сохранённый текст и не помечают проект изменённым.

Исходники модуля находятся в Modbus/Models, Modbus/Services, Modbus/ViewModel и Modbus/View. EditingMode создаёт сервис, регистрирует IModbusService в Services/ServiceLocator и передаёт его окну. Обращение из кода:

```csharp
var modbus = ServiceLocator.Current.Get<IModbusService>();
var variable = modbus.AddVariable();
variable.Index = 10;
variable.Address = 0;
modbus.StartPolling();
// Разовое асинхронное чтение:
var value = await modbus.ReadValueAsync(10);
```

Настройки меняются в потоке интерфейса; сетевой опрос выполняется асинхронно. EditingMode освобождает сервис при завершении режима. TextComponentViewModel подписывается на значения через WeakEventManager. Атрибут Infrastructure/RuntimeStateAttribute исключает уведомления текущих значений из отслеживания изменений проекта.

ModbusService реализует IProjectDataParticipant: ProjectService сохраняет конфигурацию в Data/Modbus/settings.json внутри временного каталога и архива .simbridgescada. Текущие значения не сохраняются. При загрузке конфигурация проверяется до применения проекта, подключение автоматически не запускается. При добавлении проекта таблицы объединяются по индексам; разные подключения при непустой текущей таблице и несовпадающие определения одного индекса считаются конфликтом. Для новых сервисов с данными проекта реализуйте IProjectDataParticipant и передайте экземпляр в participants конструктора ProjectService.

## Режимы приложения и открытие проекта

По умолчанию MainWindow создаёт EditingMode. Весь состав редактора задаётся в Modes/Editing/EditingMode.cs: сервисы проекта и Modbus, типы объектов и компонентов, шаблоны UserControl, библиотека, левая и правая панели, команды, меню и горячие клавиши. В ServiceLocator регистрируются IProjectService и IModbusService. MainWindow сохраняет публичные SaveProject/LoadProject/SaveWorkspace/LoadWorkspace как делегирующие методы.

Для другого режима реализуйте Modes/IApplicationMode: Initialize(MainWindow) настраивает окно, CanClose() проверяет возможность выхода, Dispose() освобождает ресурсы. Передайте экземпляр в `new MainWindow(new MyMode())`. Конструктор с параметром запускает только переданный режим; сервисы редактора не создаются автоматически. В EditingMode.Dispose закрываются его окна, освобождаются сервисы и снимаются регистрации, шаблоны и горячие клавиши. Новый режим может задать свои DataContext и Content.

«Открыть» и LoadProject заменяют текущий проект целиком после успешной проверки файла. Восстанавливаются все схемы, объекты, компоненты, порядок открытых вкладок, активная вкладка, настройки сервисов и дополнительные данные из архива. Изменённые экземпляры со старым Id тоже заменяются сохранёнными. Вкладки, закрытые в сохранении, остаются закрытыми; пустой проект очищает каталог. Старый опрос Modbus останавливается, окно его настроек закрывается, новые настройки загружаются без автоматического подключения. Ошибка проверки файла сохраняет текущий проект.

Перетаскивание файла остаётся отдельным действием импорта и добавляет содержимое к текущему проекту. Это использует `EditingMode.LoadWorkspace(path, mergeProject: true)` и `IProjectService.LoadProject(path, merge: true)`. Обычное открытие использует merge=false. Старый JSON-проект .simbridge-project при открытии также заменяет схемы и сбрасывает отсутствующие в нём настройки сервисов; следующее сохранение предлагает современный архив .simbridgescada.
